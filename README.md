# subway_daily DATE PART 1: 기본 날짜 기준 만들기

서울 지하철 일별 승하차량 Raw Data를 상권 이동 분석에 활용하기 위해, 날짜 기준과 주요 컬럼 구조를 정리하는 전처리 프로젝트입니다.

상권 이동 포트폴리오에서 공통으로 사용하는 `subway_daily` 데이터셋을 만들기 전, Raw Data의 `사용일자`를 분석 가능한 날짜 형식으로 변환하고 평일·주말 기준을 만드는 DATE PART 전처리 과정을 담고 있습니다.

여기서는 이 전처리 과정을 실제 데이터로 쉽게 확인할 수 있도록 홍대입구역을 예시로 사용했습니다. 전체 서울 지하철 원본 데이터나 실제 상권 이동 포트폴리오에 사용된 11개 역 데이터는 저장소에 포함하지 않고, 대신 2026년 4월 홍대입구역 데이터만 추린 미니 샘플을 통해 실제 전처리 구조를 보여줍니다.

## 프로젝트 목적

서울 지하철 Raw Data의 `사용일자`는 `20260401`과 같은 8자리 값으로 제공됩니다. 날짜처럼 보이지만 그대로는 연도·월·일 단위의 분석이나 기간 조건 설정에 활용하기 불편합니다.

이 프로젝트에서는 `사용일자`를 표준 날짜 형식으로 변환하고 `year`, `month`, `day`를 분리합니다. 또한 각 날짜의 요일을 내부적으로 판별해 `date_type`을 `평일`과 `주말`로 구분합니다.

최종 결과는 이후 상권별 유동 흐름을 비교하고 다른 데이터셋과 결합할 때 공통 기준으로 사용할 `subway_daily` 분석용 데이터셋입니다.

## 전처리 전후 비교

### Raw Data

| 사용일자     | 노선명 | 역명   | 승차총승객수 | 하차총승객수 |
| -------- | --- | ---- | -----: | -----: |
| 20260401 | 2호선 | 홍대입구 | 73,700 | 77,510 |

### Processed Data

| date       | year | month | day | date_type | line_name | station_name | daily_in_passengers | daily_out_passengers | daily_total_passengers |
| ---------- | ---: | ----: | --: | --------- | --------- | ------------ | ------------------: | -------------------: | ---------------------: |
| 2026-04-01 | 2026 |     4 |   1 | 평일        | 2호선       | 홍대입구역        |              73,700 |               77,510 |                151,210 |

Raw Data의 의미는 유지하면서 분석 단계에서 반복적으로 사용하기 좋은 이름으로 컬럼을 정리했습니다.

* `사용일자` → `date`
* `노선명` → `line_name`
* `역명` → `station_name`
* `승차총승객수` → `daily_in_passengers`
* `하차총승객수` → `daily_out_passengers`
* 승차와 하차 인원의 합계 → `daily_total_passengers`

Raw Data의 `역명` 값에는 `역` 표기가 없어, 상권명·지역명과 구분하고 역 단위 데이터임을 명확히 하기 위해 이름 끝에 `역`을 붙입니다.

원본의 노선명은 현재 노선도에서 사용하는 명칭에 맞춰 정리합니다.

| Raw Data   | Processed Data |
| ---------- | -------------- |
| `2호선`      | `2호선`          |
| `경의선`      | `경의중앙선`        |
| `공항철도 1호선` | `공항철도`         |

## 전처리 흐름

```text
홍대입구역 미니 Raw Data
                 ↓
사용일자 형식 및 실제 날짜 확인
                 ↓
date, year, month, day 생성
                 ↓
평일·주말 기준의 date_type 생성
                 ↓
분석용 영문 컬럼명·노선명으로 정리
                 ↓
일별 총 승하차 인원 계산
                 ↓
subway_daily 분석용 데이터셋
```

## DATE PART 기준

날짜 관련 컬럼은 다음 기준으로 만듭니다.

| 컬럼          | 설명                           |
| ----------- | ---------------------------- |
| `date`      | `YYYY-MM-DD` 형식의 사용 날짜       |
| `year`      | 사용 연도                        |
| `month`     | 사용 월                         |
| `day`       | 사용 일                         |
| `date_type` | 월요일~금요일은 `평일`, 토요일·일요일은 `주말` |

이 단계에서는 `요일` 컬럼을 별도로 만들지 않습니다. `date_type`을 만드는 데 필요한 요일 정보는 전처리 과정에서만 사용합니다.

## 공휴일 처리 범위

현재 `date_type`은 요일을 기준으로 `평일`과 `주말`만 구분하며, 공휴일 여부는 반영하지 않습니다. 따라서 공휴일도 해당 날짜의 요일에 따라 이 단계에서는 `평일` 또는 `주말`로 분류됩니다.

공휴일 보정은 상권 이동 분석의 다음 전처리 단계에서 별도로 진행할 예정입니다. 한국천문연구원 API를 기반으로 공휴일 기준 테이블(holiday master)을 만든 뒤, `date`를 기준으로 `subway_daily`와 결합해 요일 구분과 별개로 실제 공휴일에 해당하는 날짜를 식별합니다.

이 저장소에서는 Raw Data의 날짜 형식을 변환하고 요일에 따라 평일·주말을 구분하는 DATE PART 전처리에 집중하며, 공휴일 데이터 생성과 결합은 별도의 단계로 분리합니다.

## 폴더 구조

```text
.
├─ data/
│  └─ sample/
│     ├─ raw_subway_daily_sample.csv
│     └─ processed_subway_daily_sample.csv
├─ src/
│  └─ preprocess_subway_daily_date.py
├─ README.md
└─ requirements.txt
```

* `raw_subway_daily_sample.csv`: 2026년 4월 홍대입구역 3개 노선, 90행의 실제 미니 샘플
* `processed_subway_daily_sample.csv`: 같은 90행을 `subway_daily` 컬럼 구조로 변환한 결과
* `preprocess_subway_daily_date.py`: 날짜 기준 생성과 컬럼 정리를 수행하는 전처리 코드

## 실행 방법

Python 3.10 이상 환경을 권장합니다.

```bash
python -m venv .venv
```

가상환경을 활성화한 뒤 필요한 패키지를 설치합니다.

```bash
pip install -r requirements.txt
```

기본 설정으로 실행하면 샘플 Raw Data를 읽어 Processed Data를 다시 생성합니다.

```bash
python src/preprocess_subway_daily_date.py
```

실제 파일을 처리할 때는 입력과 출력 경로를 지정할 수 있습니다.

```bash
python src/preprocess_subway_daily_date.py \
  --input data/raw/subway_daily.csv \
  --output data/processed/subway_daily.csv
```

입력 CSV에는 `사용일자`, `노선명`, `역명`, `승차총승객수`, `하차총승객수` 컬럼이 필요합니다. 원본의 `등록일자`처럼 이번 분석에 사용하지 않는 컬럼은 결과에서 제외합니다. `사용일자`가 8자리 형식이 아니거나 실제 달력에 없는 날짜라면 해당 문제를 확인할 수 있도록 오류를 발생시킵니다.

## 이 프로젝트에서 보여주고자 한 점

상권 이동 분석에서 날짜는 여러 데이터셋을 연결하는 기준이 됩니다. 따라서 날짜를 단순히 보기 좋은 형태로 바꾸는 데서 끝내지 않고, 이후 분석과 결합 과정에서 반복해서 사용할 수 있는 공통 구조로 만드는 것이 중요합니다. 저장소는 `subway_daily` 데이터셋의 날짜 기준을 먼저 정의하고, 원본 컬럼을 분석용 이름으로 정리하며, 승하차 합계를 계산하는 과정을 재현할 수 있도록 구성했습니다. 이후에는 holiday master, 상권 정보, 공간 단위 데이터와 순차적으로 결합해 상권 이동 분석으로 확장할 수 있습니다.
